# 需求文档

# 0注意

全局校验法则:

*   用户名只允许数字、字母、汉字的组合, 且不为null.
    
*   用户账号只允许6-18位数字, 且不为null
    
*   用户密码必须为6-18位数字、字母的组合, 且不为null.
    

*   客户名字只允许数字、字母、汉字以及"."以及"@"的组合, 且不为null.
    
*   客户地址只允许数字、字母、汉字以及"."以及"-"以及"/"的组合, 且不为null.
    

*   产品名字只允许数字、字母、汉字以及"."以及"@"以及"-"的组合, 且不为null.
    
*   净含量允许数字、字母以及".", 且数字先行且不为null.
    
*   规格允许数字、字母, 且数字先行且不为null.
    
*   tag为产品的一些特点, 并不required, 前端需要提醒输入规则(产品特点之间用规定的分割符号进行分离)
    
    *   输入规则: \[特点1\](";"/" "/"、" )\[特点2\](;)
        
*   金额不能为负数
    
*   数量应为自然数
    
*   开始时间 < 结束时间
    

crud法则:

*   当执行insert操作时, 自动生成created\_time, modified\_time, modified\_user.
    
    *   按照规则自动生成主键
        
    *   除特殊说明, insert操作后的主键, 都应由雪花规则自动生成.
        
        *   发票的id的生成方式: prefix + 时间 + 开票人姓名
            
            *   prefix: SALE
                
            *   时间: YYYYMMDDhhmmss
                
            *   开票人姓名: 中文转拼音
                
    *   created\_time = modified\_time = 当前执行此操作的时间, 精确到秒
        
    *   modified\_user = 当前执行此操作的user\_id = 当前session的user\_id
        
*   当执行update操作时, 覆盖modified\_time,modified\_user
    
    *   不修改created\_time
        
    *   modified\_time = 当前执行此操作的时间, 精确到秒
        
    *   modified\_user = 当前执行此操作的user\_id = 当前session的user\_id
        
*   当执行delete操作时, 覆盖modified\_time,modified\_user
    
    *   是逻辑删除, deleted置为1
        
    *   modified\_time = 当前执行此操作的时间, 精确到秒
        
    *   modified\_user = 当前执行此操作的user\_id = 当前session的user\_id
        
*   涉及到级联更新, 多表更新时, 应保证事务性, 一张表更新失败,则该事务失败, 所有表回滚
    

对前端的功能要求:

*   填写日期或者时间时, 前端应同时支持用户手动输入和提供日历框给用户选择
    
*   在查询时, 前端支持 用户每输入一个字, 下拉框中从对应数据库中模糊查询出可以匹配的数据
    
    *   eg
        
        *   场景: 用户想要查询客户汇款记录,
            
        *   用户行为: 用户在 客户纬度-客户名字 filter中, 输入了“周”字
            
        *   前端行为: 从客户信息表中检索含有“周”字的所有客户, 并在 客户纬度-客户名字 以下拉框的形式展示供用户选择.
            

# 1登陆&注册

最基础的登陆和注册功能.

*   后续所有api都需要鉴权, 即如果用户未经登陆直接访问后续api, 将会被拦截, 并强制跳转回\[登陆&注册\] 界面.
    
*   前端需提示用户的输入规则
    
    *   用户账号只允许6-18位数字, 且不为null
        
    *   用户密码必须为6-18位数字、字母的组合
        
    *   密码默认为 密文 展示(即\*), 前端支持\[展示密码\]功能, 密码变 明文
        
*   登陆:
    
    *   前端支持记住账号、记住密码功能.
        
    *   根据账号、密码信息, 去用户信息表中查询.
        
        *   查不到账号 
            
            *   提示用户, \[该账号未注册\]
                
        *   查到账号 但密码不匹配
            
            *   提示用户, \[错误的密码\]
                
        *   查到账号, 密码也匹配, 但是已经被逻辑删除
            
            *   提示用户, \[该账号已被删除\]
                
        *   登陆成功
            
            *   用户登陆成功后, 进行鉴权, 具体权限参考\[6.1.1权限说明\], 后续访问api时, 根据不同的权限展示不同的功能. 
                
            *   用户登陆成功后,应有一个session的全局上下文, 能够去获取登陆成功的用户信息(用户id、用户账号、用户权限)
                
            *   跳转到主页, 即出库数据可视化页面
                
*   注册:
    
    *   如果用户信息表中有该用户账号, 提示用户, \[该账号已注册\]
        
    *   应有\[确认密码\]一栏, 保证用户第一次输入的密码和第二次输入的密码一致
        
    *   注册成功后,按照规则生成随机的用户名, 自动生成用户id作为主键, 获取当前时间为created\_time和modified\_time, modified\_user为自己(刚刚生成的用户id)
        

主页: 默认为可视化

左侧栏依次为可视化、出库发票、货款录入、罚款录入、查询、后台管理. 点击后可跳转到对应功能.

右上角: 一个小tab, 展示用户的登陆信息, 点击后有\[编辑个人信息\]、\[下线\]等必要的功能.

# 3出库发票

出库发票表、出库产品表

填写信息:

*   客户纬度(客户姓名、 客户地址), required
    
*   开票日期(合法的日期, 精确到日), required
    
*   开票人(前端应默认展示当前用户的名字为开票人, 也应该支持用户手动修改), required
    
*   出库产品
    
    *   一次出库发票可能会有多个产品出库, 用户可以动态地点击 “+” 号 添加一个出库产品, 也可以点击“-”号 删除已经填写的出库产品
        
    *   出库发票中的出库产品应该包括产品纬度 以及 单价 以及 数量 以及 出库金额
        
        *   当用户填写完产品纬度和客户纬度后, 应支持自动从 客户-产品单价表 中查询该客户该产品对应的单价, 并展示在单价这一格. 如果没有结果, 则不展示. 当然, 也支持用户手动修改单价.
            
        *   当单价和数量有数值后, 前端应自动计算: 出库金额 = 单价 \* 数量.  当然, 也支持用户手动修改出库金额(如果手动修改此出库金额, 应当弹出警告, \[用户正在修改出库金额\]).
            
    *   应该有一个出库总金额, 实时记录.
        
        *   每填写完一个出库产品, 动态更新该值, 出库总金额 = SUM(出库产品的出库金额)
            
        *   该值不允许用户更新
            
*   运费
    
    *   一次出库发票可能会有运费, 也可能没有.  用户可以动态地点击 “+” 号 添加一个运费, 也可以点击“-”号 删除已经填写的运费
        
    *   运费有可能是生产商出, 也有可能是客户出. 运费这一栏应该必须让用户选择 \[是否出运费\], 如果选择“是”, 此次运费由生产商出, 不计入本次出库发票记录中的总金额; 如果选择“否”, 此次运费由客户出, 计入本次出库发票记录中的总金额.
        
*   备注
    
    *   200字以内, 用户未输入时, 前端默认展示文案\[补废xx、赠送xx\]
        
*   总金额
    
    *   如果此次运费由生产商出, 那么总金额 = 出库总金额 + 运费; 否则, 总金额 = 出库总金额
        
    *   该值不允许用户更新
        

check:

*   如果不存在该客户纬度的客户, 那么弹出警告 \[该客户未注册, 请先注册\], \[注册\]二字应带有跳转链接, 点击后用户可跳转 \[7.2.1客户信息管理\]
    
*   如果不存在该产品纬度的产品,那么弹出警告 \[该产品未注册, 请先注册\], \[注册\]二字应带有跳转链接, 点击后用户可跳转 \[7.3产品管理\]
    
*   check失败则不允许录入.
    
*   保留该用户session中, 最近一次的填写信息.
    

check成功后, 事务性更新出库发票表、出库产品表, 根据字段含义填入,

## 6.5客户对账记录

展示某个客户某段时间往来金额记录

*   客户对账来自于出库发票表、出库产品表、客户汇款表、客户罚款表,
    
*   支持根据客户纬度、时间 等过滤条件 list 出记录.
    
    *   分三个区域
        
        *   展示发票id、发票出库金额、发票运费、发票总金额
            
            *   点击发票id后, 可以查看详细的发票记录, 包括产品出库
                
                *   根据发票id查出库产品表
                    
            *   该区域需要统计filter后的总金额
                
        *   展示汇款记录
            
            *   该区域需要统计filter后的总金额    
                
        *   展示罚款记录
            
            *   该区域需要统计filter后的总金额
                
    *   根据三个总金额汇总最终金额: 客户未付款 = 罚款总金额 + 发票总金额 - 汇款总金额
        
*   不支持分页逻辑.
    
*   不支持任何插入/修改/删除功能, 
    
*   右边提供导出, 可以将本次filter出的所有记录 导出到一张excel表中.
    

# 7后台管理

## 7.1用户信息管理

用户信息表

### 7.1.1权限说明

用户一共三种权限:

| 用户权限 | 拥有的权限 | 没有的权限 |
| --- | --- | --- |
| 超级管理员(super) | 1.  拥有\[后台管理\]等, crud\[用户权限\]\[客户\]\[产品\]等权限<br>    <br>2.  拥有\[开票\]、\[货款录入\]、\[罚款录入\]等, insert/update/delete 数据的权限<br>    <br>3.  拥有\[查询\]等, select数据的权限 | / |
| 管理员(admin) | 1.  拥有\[开票\]、\[货款录入\]、\[罚款录入\]等, insert/update/delete 数据的权限<br>    <br>2.  拥有\[查询\]等, select数据的权限 | 1.  \[后台管理\]等, crud\[用户权限\]\[客户\]\[产品\]等权限 |
| 浏览者(viewer) | 1.  拥有\[查询\]等, select数据的权限 | 1.  拥有\[后台管理\]等, crud\[用户权限\]\[客户\]\[产品\]等权限<br>    <br>2.  拥有\[开票\]、\[货款录入\]、\[罚款录入\]等, insert/update/delete 数据的权限 |

当用户首次注册时, 权限被定义为 \[viewer\].

### 7.1.2用户管理

用户账号 幂等

*   支持根据用户名、用户账号、用户权限 等过滤条件 list 出用户.
    
*   支持分页逻辑.
    
*   每一条用户记录后有编辑/删除功能. 
    
*   右侧会有一个添加用户功能.
    
*   仅\[super\]拥有编辑/删除/添加功能的权限.
    
    *   点击编辑后, 可以编辑用户的账户信息, 包括用户密码、用户权限,
        
    *   点击删除后, 可以从用户信息表中逻辑删除该用户信息记录, 
        
    *   点击添加后, 弹出表单, 填写必须的用户信息(用户名、用户账号、用户密码、用户权限), 进行check
        
        *   check逻辑:
            
            *   如果用户信息表中已经有该用户账号, 则提醒用户\[已存在该用户记录\]
                
*   其他权限用户仅支持查询功能.

### 7.2.2客户-产品单价 管理

客户-产品单价表

客户id+产品id 幂等

生产商的每个产品的单价, 会根据不同的客户信息、生效日期 动态的更改.

*   支持根据客户纬度、产品纬度、生效日期 等过滤条件 list 出客户-产品单价记录.
    
    *   客户纬度: 客户名字、客户地址
        
        *   当需要使用客户纬度进行查询时, 根据信息从客户信息表中list出满足条件的客户id
            
    *   产品纬度: 产品名、产品规格、产品净含量
        
        *   当需要使用产品纬度进行查询时, 根据信息从产品信息表中list出满足条件的产品id
            
    *   如果生效日期start为null, 则把生效日期end纳入过滤条件
        
    *   如果生效日期end为null, 则把生效日期start纳入过滤条件
        
    *   如果表中有客户纬度、产品纬度, 但是单价为null, 那么前端应该在单价那一格展示\[未添加单价\]
        
*   支持分页逻辑.
    
*   每一条客户-产品单价记录后有编辑/删除等功能. 
    
*   仅\[super\]拥有编辑/删除/添加的权限.
    
    *   点击编辑后, 可以编辑客户-产品单价记录, 包括产品单价&生效日期. 
        
    *   点击删除后, 可以从表中逻辑删除该客户-产品单价记录. 
        
    *   点击添加后, 弹出表单, 填写必须的客户信息&产品信息&产品单价&生效日期, 进行check
        
        *   check逻辑: 
            
            *   若客户-产品单价表中已经存在该客户id+产品id, 则提醒用户\[已存在该客户-产品单价记录\]
                
*   其他权限用户仅支持查询功能.
    

## 7.3产品管理

产品信息表

产品名+净含量+规格 幂等

*   支持根据产品名、净含量、规格、tag等过滤条件 list 出产品.
    
    *   tag为模糊查询
        
*   支持分页逻辑.
    
*   每一条产品记录后有编辑/删除等功能. 
    
*   右侧会有一个添加产品功能
    
*   仅\[super\]拥有编辑/删除/添加产品功能的权限.
    
    *   点击编辑后, 可以编辑产品的基础信息,包括产品名、净含量、规格、tag, 
        
    *   点击删除后, 可以从客户信息表中逻辑删除该产品记录, 
        
    *   点击添加后, 弹出表单, 填写必须的产品信息(产品名、净含量、规格), 进行check
        
        *   check逻辑:
            
            *   如果产品信息表中已经有该产品名+净含量+规格, 则提醒用户\[已存在该产品记录\]
                
*   其他权限用户仅支持查询功能.
